# 藥品地圖：離線單機版

由藥品地圖專案衍生，提供藥局同業在單一電腦管理藥品位置。無須 Firebase、雲端帳號或網路連線；資料保存在程式資料夾的 `data/database.json`。

## Windows 使用者

下載 Releases 中的 `drugmap-offline-windows.zip`，完整解壓縮到可寫入的資料夾，雙擊 `Start.cmd`。瀏覽器開啟 <http://127.0.0.1:3210>；如果首次開啟時尚未連線，稍候重新整理。使用期間保留命令視窗，關閉視窗即停止服務。不要直接在 ZIP 裡執行。

離線包包含 Node.js 執行環境與網頁資源，不需安裝 Node.js 或執行 npm。首次使用是空白藥品清單。

## v1.1.0 更新

- 新增「區間消耗」：讀取調劑明細 Excel / CSV，以日期區間彙總藥品用量，再依軌道、藥櫃和層數查看。
- 明細格式沿用線上版：A 欄日期、D 欄健保碼、H 欄數量。支援民國日期及 Excel 日期數值；只保留彙總結果，不儲存病人姓名、身分證號或原始明細。
- 儲存的消耗統計會取代前次統計，並納入完整備份與還原。明細上傳與管理區在桌面寬度顯示，與線上版一致。
- CSV 日期先驗證再統計，避免不存在的日期被套件自動修正而計入錯誤區間。
- 同一健保碼同時出現在一般藥品與少用藥品時，消耗統計優先對應已上架紀錄，避免櫃位用量被遮蔽。
- 新增少用藥品時，自動標記為本輪盤點已確認。
- 批次修改與匯出按鈕移至少用藥品工具列，匯出編輯欄位改為緊湊版面。

### 從 v1.0.0 更新

先下載完整備份並關閉舊程式，將新版解壓縮至另一個資料夾，啟動新版後還原備份。也可在關閉程式後，將舊版的整個 `data` 資料夾複製到新版根目錄。資料格式保持相容，不需重新建檔；不要同時執行新舊版。

## 首次設定

1. 在「首次建檔」匯入藥品資料，或進入「藥品管理」手動建立。
2. 設定櫃位布局及庫存位置，再使用「上架模式」指定位置。
3. 首頁可依名稱、健保碼或院內碼查詢；未上架藥品需先完成位置設定才會出現在位置查詢。
4. 「少用藥品」提供收納位置、數量及盤點功能。
5. 「備份與還原」可匯出完整資料。定期把備份存到其他磁碟。

單機版不設帳號權限，能操作這台電腦的人都能修改資料。服務只監聽 `127.0.0.1`，不供區域網路或多人連線使用。請勿同時啟動多個指向相同資料夾的服務。

## 資料保存與搬移

關閉或重新啟動瀏覽器不會清除資料。更新程式前先備份，將原本 `data` 資料夾保留於新版根目錄，或使用備份還原。還原前自動建立 `data/before-restore-*.json`，可用相同還原功能復原。不要把自己的 `data` 資料夾上傳 GitHub。

新程式不會自動讀取原 Firebase 藥局資料；原專案仍可獨立使用。健保藥品索引是隨程式附帶的靜態版本，離線不會自動更新。

## 開發者：從原始碼建置

需要 Node.js 22 以上及 npm。首次安裝套件需要網路，完成建置後執行不需要網路。

```sh
npm ci
npm run build
npm start
```

開啟 <http://127.0.0.1:3210>。`npm run dev` 僅供介面開發，資料 API 由單機服務提供，完整功能請使用 build + start。可用 `DRUGMAP_DATA_DIR` 指定資料資料夾，`PORT` 指定連接埠。

```sh
npm test
npm run lint
npm run package:windows
```

Windows 封裝需要在專案根目錄提供對應 Node.js 版本的官方 `NODE-LICENSE.txt`。產物在 `release/v版本號/drugmap-offline-windows`（本版為 `release/v1.1.0/drugmap-offline-windows`）。封裝不包含使用者資料。

連網時可執行 `npm run sync:nhi` 更新官方索引，之後重新建置。資料來源及第三方授權見 THIRD_PARTY_NOTICES.md。

此工具用於位置與盤點管理，不提供處方判斷或用藥建議。
